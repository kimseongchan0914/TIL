# Spring Security / JWT 정리

## 쓰는 이유

웹 서비스 만들 때 무조건 필요한 게 “로그인 + 권한 관리”다.

* Spring Security → 인증/인가 전체 관리
* JWT → 로그인 상태를 유지하는 방법 (토큰 방식)

둘은 거의 세트로 같이 쓴다.

---

## Spring Security란?

스프링에서 **인증 + 인가를 처리해주는 보안 프레임워크**

기본적으로 하는 일

* 로그인 처리 (인증)
* 권한 체크 (인가)
* URL 접근 제한
* 세션 관리

---

## 기본 동작 흐름

1. 사용자가 요청 보냄
2. Spring Security 필터가 먼저 가로챔
3. 인증 여부 확인
4. 권한 확인
5. 통과하면 컨트롤러로 전달

핵심:
**컨트롤러 가기 전에 다 검사한다**

---

## 인증 / 인가 흐름 (중요)

1. 로그인 요청
2. 인증 성공
3. 인증 정보 저장
4. 이후 요청마다 인증 확인
5. 권한 체크 후 처리

---

## JWT (Json Web Token)

로그인 상태를 유지하기 위한 **토큰 방식 인증**

서버가 세션을 저장하지 않고
토큰을 클라이언트에게 넘겨준다.

---

## JWT 구조

JWT는 3부분으로 구성됨

```
Header.Payload.Signature
```

* Header → 토큰 타입, 알고리즘
* Payload → 사용자 정보 (id, role 등)
* Signature → 위조 방지용 서명

---

## JWT 동작 흐름

1. 로그인 요청
2. 서버가 사용자 확인
3. JWT 생성 후 클라이언트에게 전달
4. 클라이언트는 토큰 저장
5. 요청할 때마다 토큰 포함

```
Authorization: Bearer 토큰값
```

6. 서버가 토큰 검증 후 처리

---

## Spring Security + JWT 흐름

1. 로그인 요청
2. 인증 성공
3. JWT 발급
4. 이후 요청 시 토큰 전달
5. 필터에서 토큰 검증
6. 인증 정보 설정
7. 권한 체크 후 처리

---

## 핵심 개념 정리

### 1. Filter

요청을 가로채서 처리하는 구조
JWT 검증도 여기서 함

---

### 2. SecurityContext

인증된 사용자 정보를 저장하는 공간

---

### 3. UserDetails

사용자 정보를 담는 객체

---

## 세션 방식 vs JWT 방식

세션 방식

* 서버가 로그인 상태 저장
* 서버 메모리 사용

JWT 방식

* 서버가 상태를 저장하지 않음
* 토큰으로 인증 처리

---

## JWT 장점

* 서버가 상태를 안 들고 있음 (Stateless)
* 확장성 좋음
* 모바일/웹에서 사용하기 편함

---

## JWT 단점

* 토큰 탈취 시 위험
* 만료 전까지 강제 로그아웃 어려움

# 2일차 정리 제네릭 (Generics)

---

## 한 줄 정의
> 제네릭 = **타입을 나중에 정할 수 있게 비워두는 것** (타입을 위한 빈칸)

## 붕어빵 틀 비유
- 틀(구조)은 하나인데, 속재료(타입)만 바꿔서 여러 종류를 만든다.
- `List`라는 틀에 `<String>`을 넣으면 문자열 리스트, `<Integer>`를 넣으면 정수 리스트.

## 왜 필요할까
제네릭이 없으면 `Object`로 만들어야 하는데, 두 가지 문제가 생긴다.

```java
Box box = new Box();
box.set("hello");
String s = (String) box.get();      // 매번 형변환(캐스팅) 필요
Integer n = (Integer) box.get();    // 컴파일은 되지만 실행하면 터짐!
```

제네릭을 쓰면 해결된다.

```java
Box<String> box = new Box<>();
box.set("hello");
String s = box.get();   // 캐스팅 불필요
box.set(123);           // 컴파일 에러 → 잘못된 타입을 미리 차단
```

**핵심 장점 2가지**
1. 형변환(캐스팅)을 안 해도 된다.
2. 잘못된 타입은 컴파일 시점에 바로 걸러진다 (실행 전에 안전).

## 직접 만들기 — 제네릭 클래스
```java
class Box<T> {          // "이 상자는 T 타입을 담는다"
    private T item;

    public void set(T item) {
        this.item = item;
    }

    public T get() {
        return item;
    }
}
```
`Box<String>`이라고 쓰는 순간, 클래스 안의 모든 `T`가 `String`으로 확정된다.

## 타입 파라미터 관례
| 글자 | 의미 | 주로 쓰는 곳 |
|---|---|---|
| `T` | Type | 일반적인 타입 |
| `E` | Element | 컬렉션의 원소 (`List<E>`) |
| `K` | Key | Map의 키 |
| `V` | Value | Map의 값 |

예: `Map<String, Integer>` → K = String(키), V = Integer(값)

## 더 알아둘 것 (나중에 실무에서 마주치면 찾아보기)
- **제네릭 메서드**: 메서드 하나만 제네릭으로. 반환 타입 앞에 `<T>`를 붙인다.
  ```java
  public <T> T getFirst(List<T> list) {
      return list.get(0);
  }
  ```
- **와일드카드 `?`**: 타입을 정확히 몰라도 될 때.
  ```java
  public void printAll(List<?> list) { ... }
  ```
- **경계 와일드카드**: `List<? extends Number>`, `List<? super Integer>`

# 1차 캐시
1차 캐시는 영속성 컨텍스트 내부에서 Entity를 저장하고 관리하는 메모리 공간이다.

JPA는 Entity를 조회하거나 저장할 떄 먼저 1차 캐시를 확인한 후, 필요한 경우에만 데이터베이스에 접근할수 있도록 한다.

즉 불필요한 데이터는 데이터베이스 조회를 줄여 성능을 향상 시켜주는 역할을 한다.

# 2. 1차 캐시가 필요한 이유
데이터베이스에 접근하는 작업은 메모리에 접근하는 것보다 시간이 오래 걸린다.

동일한 데이터를 여러번 조회할때마다 데이터베이스에 접근하면 성능이 저하된다. 

JPA는 영속성 컨텍스트내에 Entity를 저장해두고 같은 데이터를 다시 요청하면 데이터베이스가 아닌 1차캐시에서 조회한다.

이를 통해 데이터베이스의 조회를 줄일수 있다.

# 3. 1차 캐시의 구조
1차 캐시는 기본 키를 KEY로 사용하여 Entity를 저장한다.

# 4. 조회 과정
예를 들어 다음과 같이 Entity를 조회한다고 가정하면

    Member member = entityManager.find(Member.class, 1L);

JPA는 다음과 같은 순서로 동작한다

find()

↓

1차 캐시 조회

↓

Entity 존재

↓

Entity 반환

이미 1차 캐시에 존재 한다면 데이터베이스를 조회 하지 않는다.

#### 1차 캐시에 없는 경우
find()

↓

1차 캐시 조회

↓

없음

↓

데이터베이스 조회

↓

1차 캐시에 저장

↓

Entity 반환

처음 한번만 데이터베이스를 조회하고 이후에는 캐시를 사용한다.

# 5. 동일성 보장

1차 캐시는 같은 Entity를 여러번 조회 하더라도 동일한 객체를 반환한다.

    Member member1 = entityManager.find(Member.class, 1L);
    Member member2 = entityManager.find(Member.class, 1L);

    System.out.println(member1 == member2);

    실행결과

    true

== 연산자가 트루인 이유는 두 변수가 같은 객체를 참조 하기 때문이다

# 6. 1차 캐시의 특징
* 영속성 컨텍스트 내부에 존재한다.
* 기본 키(PK)를 기준으로 Entity를 저장한다.
* 같은 Entity를 다시 조회하면 데이터베이스를 조회하지 않는다.
* 동일한 객체를 반환하여 동일성을 보장한다.
* 데이터베이스 접근 횟수를 줄여 성능을 향상시킨다.

# 8. 1차 캐시는 언제 사라질까?
1차 캐시는 영속성 컨텍스트가 종료되면 함께 삭제된다.

    entityManager.clear();
이거 같은 경우는 1차 캐시가 초기화 된다.

또는

    entityManager.close();

또는 트랜잭션이 종료되어 영속성 컨텍스트가 종료되는 경우이다.

즉 1차 캐시는 영속성 컨텍스트와 생명주기를 함께한다.

# 9. 1차 캐시와 데이터베이스 비교

| 항목    | 1차 캐시         | 데이터베이스   |
| ----- | ------------- | -------- |
| 저장 위치 | 영속성 컨텍스트(메모리) | 디스크      |
| 조회 속도 | 빠름            | 상대적으로 느림 |
| 조회 기준 | 기본 키(PK)      | SQL      |
| 생명주기  | 영속성 컨텍스트와 동일  | 영구 저장    |

# 3. 지연로딩과 프록시

## 1. 한 줄 요약
JPA의 지연로딩도 **프록시**로 구현된다. 연관 엔티티를 실제 객체 대신 **프록시**로 넣어두고, 값이 필요한 순간에 DB 쿼리를 날려 초기화한다.

---

## 2. 즉시로딩 vs 지연로딩
| 종류 | 설정 | 동작 |
|------|------|------|
| 즉시로딩 | `FetchType.EAGER` | 엔티티 조회 시 연관 엔티티도 **바로 함께** 조회 |
| 지연로딩 | `FetchType.LAZY` | 연관 엔티티는 **프록시**로 두고, 사용 시점에 조회 |

**기본값**
- `@ManyToOne`, `@OneToOne` → EAGER
- `@OneToMany`, `@ManyToMany` → LAZY
- **실무 권장: 전부 LAZY + 필요할 때 fetch join**

---

## 3. 동작 원리
```java
@ManyToOne(fetch = FetchType.LAZY)
private Team team; // 실제로는 Team의 프록시 객체
```
```java
Member member = em.find(Member.class, 1L);
member.getTeam();           // 아직 프록시, 쿼리 안 나감
member.getTeam().getName(); // ← 이때 SELECT 실행 (프록시 초기화)
```

### 초기화 흐름
```
1. getTeam().getName() 호출
2. 프록시가 "초기화 안 됨" 감지
3. 영속성 컨텍스트에 실제 엔티티 요청
4. DB SELECT 실행
5. 실제 엔티티 연결 → 값 반환
```
한 번 초기화되면 이후엔 캐시된 값 사용.

---

## 4. AOP 프록시 vs JPA Lazy 프록시
**개념 동일:** "원본을 감싸서, 필요할 때 진짜 동작 수행."

| 구분 | 목적 | 진짜 동작 시점 |
|------|------|---------------|
| AOP 프록시 (@Transactional) | 부가 기능(트랜잭션) 삽입 | 메서드 호출 시 |
| Lazy 프록시 (JPA) | DB 조회를 최대한 미룸 | 값에 실제 접근할 때 |

---

## 5. LazyInitializationException (가장 중요)
### 언제?
영속성 컨텍스트(트랜잭션)가 **끝난 뒤** 프록시를 초기화하려 할 때.
```java
@Transactional
public Member getMember(Long id) {
    return em.find(Member.class, id);
} // ← 트랜잭션 종료, 영속성 컨텍스트 닫힘

// Controller에서:
member.getTeam().getName();
// ❌ LazyInitializationException!
```
### 왜?
프록시 초기화엔 DB 조회가 필요한데, 영속성 컨텍스트가 닫히면 조회 불가.

---

## 6. 해결 방법 4가지
```java
// 1) Fetch Join (가장 권장)
@Query("SELECT m FROM Member m JOIN FETCH m.team WHERE m.id = :id")
Member findWithTeam(@Param("id") Long id);

// 2) @EntityGraph
@EntityGraph(attributePaths = {"team"})
Optional<Member> findById(Long id);

// 3) DTO로 필요한 것만 조회
@Query("SELECT new com.example.MemberDto(m.name, t.name) FROM Member m JOIN m.team t")
List<MemberDto> findAllDto();

// 4) OSIV (spring.jpa.open-in-view=true, 기본 켜짐)
//    → 영속성 컨텍스트를 View까지 유지. 단, 커넥션 오래 점유 → 실무는 끄고 fetch join 권장
```

---

## 7. N+1 문제
지연로딩 상태에서 리스트를 순회하며 연관 엔티티에 접근하면 각 요소마다 쿼리 발생.
```java
List<Member> members = memberRepository.findAll(); // 쿼리 1번
for (Member m : members) {
    m.getTeam().getName(); // member마다 쿼리 N번 → 총 1+N번
}
```
**해결:** Fetch Join, `@EntityGraph`, `@BatchSize`

---

## 8. 최종 요약
- 지연로딩 = 연관 엔티티를 **프록시**로 두고 사용 시점에 조회
- AOP 프록시와 원리 개념 동일
- 영속성 컨텍스트 밖 초기화 → **LazyInitializationException**
- 해결: **Fetch Join** / `@EntityGraph` / DTO 조회
- **N+1 문제** 주의

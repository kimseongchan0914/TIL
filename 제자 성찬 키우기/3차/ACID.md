# ACID — 트랜잭션의 4대 성질

## 1. 한 줄 요약

트랜잭션이 **안전하게** 처리되기 위한 4가지 보장:
**A**tomicity(원자성), **C**onsistency(일관성), **I**solation(격리성), **D**urability(지속성).

---

## 2. A — Atomicity (원자성)

> **"All or Nothing"** — 전부 성공하거나 전부 실패

트랜잭션 안의 작업은 **하나의 단위**로 취급된다. 중간에 실패하면 이미 한 작업도 전부 되돌린다(롤백).

### 예시: 계좌이체
```
1. A 계좌에서 1만원 출금
2. B 계좌에 1만원 입금
```
- 1번은 됐는데 2번에서 실패? → **1번도 롤백**해서 없던 일로.
- "출금은 됐는데 입금은 안 됨" 같은 중간 상태는 절대 허용 안 됨.

---

## 3. C — Consistency (일관성)

> 트랜잭션 전후로 DB가 **정합성 규칙을 항상 만족**

무결성 제약(PK, FK, NOT NULL, UNIQUE, CHECK 등)이 트랜잭션 전후로 깨지지 않아야 한다.

### 예시
- "계좌 잔액은 음수가 될 수 없다"는 규칙 → 트랜잭션 후에도 유지.
- FK 제약: 존재하지 않는 팀 ID를 참조하는 멤버를 만들 수 없음.

**원자성과의 차이**
- 원자성: "전부 되거나 전부 안 되거나" (실행 방식)
- 일관성: "규칙을 항상 지킴" (데이터 상태)

---

## 4. I — Isolation (격리성)

> 동시에 실행되는 트랜잭션은 **서로 간섭하지 않음**

여러 트랜잭션이 동시에 돌아가도, 각자 혼자 실행된 것처럼 보여야 한다.

### 동시성 문제 3가지

| 문제 | 설명 |
|------|------|
| **Dirty Read** | 아직 **커밋 안 된** 데이터를 읽음 (롤백되면 유령 데이터를 읽은 셈) |
| **Non-Repeatable Read** | 같은 행을 두 번 읽었는데 **값이 다름** (사이에 다른 트랜잭션이 수정) |
| **Phantom Read** | 같은 조건으로 조회했는데 **행 개수가 달라짐** (사이에 다른 트랜잭션이 삽입) |

### 격리 수준 (Isolation Level)
낮을수록 성능↑ 안전성↓, 높을수록 안전성↑ 성능↓

| 수준 | Dirty | Non-Repeatable | Phantom |
|------|:-----:|:--------------:|:-------:|
| READ UNCOMMITTED | 발생 | 발생 | 발생 |
| READ COMMITTED | 방지 | 발생 | 발생 |
| REPEATABLE READ | 방지 | 방지 | 발생* |
| SERIALIZABLE | 방지 | 방지 | 방지 |

- **Oracle, PostgreSQL 기본:** READ COMMITTED
- **MySQL(InnoDB) 기본:** REPEATABLE READ
- *MySQL InnoDB는 REPEATABLE READ에서도 MVCC로 Phantom을 대부분 방지

### 트레이드오프
- SERIALIZABLE은 가장 안전하지만 사실상 순차 실행 → 성능 최악
- 실무는 보통 READ COMMITTED / REPEATABLE READ에서 균형

---

## 5. D — Durability (지속성)

> 커밋된 데이터는 **영구 보존**

트랜잭션이 커밋되면, 시스템 장애(정전, 서버 다운)가 나도 결과가 유지돼야 한다.

### 어떻게 보장?
- **로그 선기록(WAL, Write-Ahead Log / Redo Log)**: 변경 내용을 디스크 로그에 먼저 기록
- 장애 복구 시 로그를 재실행(replay)해서 커밋된 데이터 복원
- 메모리(버퍼)에만 있고 디스크에 안 써졌어도 로그로 복구 가능

---

## 6. 4가지 한눈에 비교

| 성질 | 키워드 | 보장 내용 |
|------|--------|-----------|
| **Atomicity** (원자성) | All or Nothing | 전부 성공 or 전부 롤백 |
| **Consistency** (일관성) | 정합성 규칙 | 무결성 제약 항상 유지 |
| **Isolation** (격리성) | 간섭 없음 | 동시 트랜잭션 서로 독립 |
| **Durability** (지속성) | 영구 보존 | 커밋되면 장애에도 유지 |

---

## 7. Spring과의 연결

- `@Transactional`이 보장하려는 게 바로 이 **ACID**
- `isolation` 옵션 = 격리 수준 조절
  ```java
  @Transactional(isolation = Isolation.READ_COMMITTED)
  ```
- 롤백(원자성)은 예외 발생 시 자동 처리
- 커밋(지속성)은 정상 종료 시 자동 처리

---

## 8. 최종 요약

- **A**: 전부 되거나 전부 안 되거나 (롤백)
- **C**: 데이터 규칙(무결성) 항상 유지
- **I**: 동시 실행 트랜잭션 서로 간섭 X → 격리 수준으로 조절
- **D**: 커밋되면 장애에도 영구 보존 (로그 기반)

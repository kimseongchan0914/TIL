# 트랜잭션(Transaction) 정리

## 1. 트랜잭션이란?
데이터베이스에서 하나의 작업 단위를 의미한다.  
여러 개의 작업을 하나로 묶어 **모두 성공하거나, 모두 실패하도록 보장**하는 개념이다.

---

## 2. 왜 필요한가

데이터 처리 중 일부만 성공하면 데이터가 깨질 수 있다.

예:
- 계좌 이체
  - A 계좌에서 돈 출금
  - B 계좌에 돈 입금

→ 출금만 되고 입금이 안 되면 문제 발생

### 핵심 목적
- 데이터 일관성 유지
- 안정적인 처리 보장

---

## 3. 트랜잭션의 특징 (ACID)

### 1) Atomicity (원자성)
- 모든 작업이 한 번에 성공하거나 모두 실패해야 한다
- 중간 상태는 허용되지 않는다

---

### 2) Consistency (일관성)
- 트랜잭션 수행 전과 후의 데이터 상태가 일관되어야 한다
- 데이터 무결성이 유지되어야 한다

---

### 3) Isolation (격리성)
- 동시에 실행되는 트랜잭션이 서로 영향을 주지 않아야 한다
- 각 트랜잭션은 독립적으로 실행된다

---

### 4) Durability (지속성)
- 트랜잭션이 성공적으로 끝나면 결과는 영구적으로 저장된다

## 5. Commit / Rollback

### Commit
- 모든 작업이 정상적으로 완료됨
- 변경 내용이 데이터베이스에 저장됨

### Rollback
- 작업 중 오류 발생
- 이전 상태로 되돌림

---

## 6. Spring에서의 트랜잭션

### 개념
Spring에서는 트랜잭션을 자동으로 관리할 수 있다.

### 방법
- `@Transactional` 어노테이션 사용

### 특징
- 메서드 단위로 트랜잭션 적용
- 예외 발생 시 자동 Rollback
- 정상 실행 시 Commit

---

## 7. 트랜잭션이 적용되는 위치

보통 Service 계층에서 사용한다.

### 이유
- 비즈니스 로직이 수행되는 곳이기 때문
- 여러 DB 작업을 하나의 단위로 묶기 위함

## 9. 핵심 정리

- 트랜잭션은 여러 작업을 하나의 단위로 묶는다
- 성공하면 Commit, 실패하면 Rollback
- 데이터의 일관성과 안정성을 보장한다

---

## 10. 한줄 정리

트랜잭션은 여러 데이터 작업을 하나로 묶어 모두 성공하거나 모두 실패하도록 보장하는 데이터 처리 단위이다.
